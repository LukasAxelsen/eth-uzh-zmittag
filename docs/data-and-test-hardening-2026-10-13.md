# 数据与测试加固实施记录（2026-10-13）

六项工单已在工作区实施，尚未提交或部署。每项均先运行失败的行为回归，
再实现并运行完整离线检查；前端仍通过统一的 `renderAll()` 更新。

| 工单 | 最终行为 |
| --- | --- |
| P0 来源健康 | 每个日期保存 ETH/UZH 独立状态及每家食堂的状态；失败记录来源、日期、食堂、阶段和原因。构建日期必须为苏黎世当天。无固定每日菜数阈值。 |
| P0 日期窗口 | 全部日期验证 ISO 日期、32 个稳定且唯一的 ID、两个 meal slot、菜名及价格/营养字段；日期索引必须恰为有菜日期的排序去重列表。未来空日及可选信息缺失合法。 |
| P1 数值 | 通用解析保留有限零值，缺失返回 None，非法数值报解析失败。价格/营养各自检查负值、单位和范围；JSON 严禁 NaN/Infinity。原始文本也保留零值。 |
| P1 闭店 | `closures.json` 仅接受有日期、食堂 ID、理由和来源/校历证据的记录；初始为空。确认闭店与空菜单、未发布和故障独立；故障不能被闭店记录或手动空日开关掩盖。 |
| P2 偏好 | 原有 savePrefs/loadPrefs 保存营业时间、价格；旧存储缺字段维持默认开启。两个处理器也改为状态变化后调用 renderAll。 |
| P2 饱和脂肪 | 唯一 UZH 营养映射接入 saturatedFat；真实 Garden 样本为 g，每 100 g 显示 2.0，每份保留 11.42562。缺字段不丢菜品。 |

抓取、最终发布检查共用 `menu_data.py`。构建先验证和暂存所有文件，再逐文件
原子替换，data.json 最后替换；请求、解析、数值、模板读取和序列化失败均不会
先覆盖已有输出。CI 的手动空工作日开关同时传入构建与发布检查，不能绕过来源、
日期或结构检查。

Food2050 的额外真实格式：Obere Mensa 返回 `menuCategory: null`、明确的日期范围，
并显示“本周没有菜单计划”。这被分类为 `not_published`，而不是确认无供应或闭店。
相同结构若没有明确的未发布说明，仍判定 `parse_failed`。已保存最小真实 fixture。

Cookpit 的真实未来空日（2026-10-17）响应为严格空对象 `{}`，记录为 `not_published`，
并允许未来/周末窗口通过。带未知非空结构的响应仍报解析失败；当天工作日整个来源
未发布时仍阻止发布，不能仅凭空响应宣称闭店或确认无供应。
