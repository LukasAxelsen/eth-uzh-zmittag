# 数据与测试加固修复工单

依据《数据与测试边界审查（2026-10-13）》整理。此文件是后续实施指令；本次部署只包含日期默认值和 UZH Food2050 解析修复，不包含以下审查建议。

## P0：区分来源健康状态与合法空菜单

在抓取结果中为 ETH、UZH 分别记录 `ok`、`confirmed_empty`、`request_failed`、`parse_failed` 等明确状态。不要把请求失败或格式变化折叠成空菜单。发布检查应确认数据是 Europe/Zurich 当天构建，并分别验证两个来源；继续要求 32 家食堂名册完整。不要设置“每天每来源至少 N 道菜”一类固定阈值；先以历史成功数据确定异常检测范围。

验收用例：ETH 正常而 UZH 返回 404、UZH 返回 HTTP 200 但结构改变、来源明确表示当天无供应、构建日期落后于苏黎世当天，四种情况分别得到可区分的结果；失败时日志指出来源和失败阶段。

## P0：验证整个预加载日期窗口

对 `days` 中的每个日期校验结构，而不只校验构建当天。检查 ISO 日期、32 个稳定且唯一的食堂 ID、meal slot 结构、非空菜名，以及价格和营养值为有限数字；检查 `availableDates` 与数据日期一致。

验收用例：合法的周末/未来空日、缺少未来照片或营养值均通过；损坏的未来日结构、重复 ID、索引引用不存在日期、NaN/Infinity 均失败，并能定位日期和字段。

## P1：修正数值边界

通用数值解析应保留合法的有限零值，以 `None` 表示缺失；禁止 NaN/Infinity 进入最终 JSON。负值、单位和范围由价格与营养字段各自校验。若 ETH 来源确实用 0 表示缺失，只在 ETH 适配层转换，不要改变 UZH 或通用解析语义。

验收用例：分别覆盖 `0`、`'0'`、数字字符串、空字符串、`None`、逗号小数、负数、`'NaN'`、`'Infinity'`；真实零值保留，缺失值为空，非法值不能静默发布。

## P1：把闭店与抓取故障分开

闭店必须由来源或校历明确确认，并作为独立状态进入数据模型。确认闭店可发布空菜单；抓取失败仍应阻止用空值覆盖有效数据。前端应给出与“暂无菜品”不同的闭店说明。保留现有工作日空数据保护，直到具备可靠的闭店来源。

验收用例：确认闭店可发布并显示闭店状态；来源超时、404 或解析失败不能伪装为闭店，也不能覆盖上一份有效数据；普通未来空日仍显示普通空菜单。

## P2：持久化营业时间与价格设置

在现有 `savePrefs` / `loadPrefs` 路径中保存并恢复 `openingTimes` 与 `prices`，继续由统一的 `renderAll()` 更新界面，不新增平行状态同步入口。

验收用例：关闭两项显示设置、保存、重载后仍为关闭；开启后重载仍为开启；升级时缺少旧存储字段仍使用当前默认值。

## P2：补齐 UZH 饱和脂肪映射

核实 Food2050 详情字段 `dish.stats.saturatedFat` 的单位与每 100 g / 每份结构，然后在唯一的 UZH 营养映射中接入 `saturated`。字段缺失时继续输出空营养值，不丢弃菜品或食堂。

验收用例：用已捕获的真实 Garden 详情断言每 100 g 和每份饱和脂肪值；缺字段样例仍成功解析，且饱和脂肪为空。

## 测试和提交顺序

每项按“先添加可复现的行为测试，再实现，再跑全量离线检查”的顺序独立完成。使用正常供餐、确认空日、来源故障、部分字段缺失四类 fixture；断言最终行为和错误分类，不只断言函数没有抛异常。网络冒烟与离线单测分开，网络检查不绑定具体菜名、照片数或每日菜数。UI 行为另用真实浏览器覆盖跨日选择、日历选中态、偏好重载和连续快速切换。
